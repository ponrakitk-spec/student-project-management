# ลำดับสาธิตสำหรับทีมและอาจารย์

วันที่ 2026-11-15 · **บทสาธิตที่เตรียมไว้ ยังไม่ใช่ผลสาธิตหรือ UATผ่านแล้ว**

อ่าน [คู่มือผู้ใช้](USER_GUIDE.md) และเปิด [โหมด UAT ROLLBACK](../uat/MANUAL_UAT.md) ก่อน เริ่มจาก flowที่ทำครบด้วย UIปัจจุบัน แล้วแสดงส่วนที่มี preconditionพร้อมตามจริง ไม่เปลี่ยนphase/สิทธิ์เพื่อให้demoผ่าน

## เตรียมผู้เล่นและข้อมูล

- นักศึกษา A/B/C สมัครด้วยอีเมลจำลองคนละบัญชี Aเริ่มเป็นหัวหน้า Bสมาชิก Cไม่มีทีมเพื่อทดสอบscope
- advisorใช้บัญชีที่ผู้ดูแลเตรียมไว้และทราบรหัสของตน ส่วนCoordinator/กรรมการใช้เฉพาะกรณีที่เตรียมphaseและบัญชีที่ได้รับแต่งตั้งไว้อย่างถูกต้องแล้ว
- แยกbrowser profile/private windowตามผู้เล่น เพื่อไม่ใช้cookieบัญชีเดียวกัน หากสลับบัญชีในหน้าต่างเดิมให้Logoutก่อน และตรวจชื่อ/บทบาทบนหน้าบัญชีทุกครั้ง
- ไม่บันทึกรหัสผ่าน/token/cookie/.envในหลักฐาน ไม่ใช้ accountsจากconcurrency manifestเป็นLoginเอง

## ช่วง A — สาธิตได้จากหน้าจอที่รวมอยู่แล้ว

| ลำดับ | ผู้เล่น / ขั้นตอน | สิ่งที่ควรเห็น |
|---|---|---|
| 1 | AสมัครและLogin | สมัครได้studentเท่านั้น; กลับหน้าบัญชี เห็นข้อมูลตน |
| 2 | Aเปิดพื้นที่ทำงาน | ยังไม่มีทีมและไม่มีปุ่มข้ามไปสร้างProject |
| 3 | Aสร้างทีม | ผู้สร้างเป็นหัวหน้า; refreshอ่านข้อมูลเดิมในรอบทดลอง |
| 4 | Bสมัคร แล้วAเพิ่มBด้วยอีเมล | Bเป็นmemberทันที; Bอ่านทีมได้แต่ใช้สิทธิ์หัวหน้าไม่ได้ |
| 5 | Aสร้างProject | BเปิดProjectเดียวกันได้; ชื่อ/คำอธิบายตรงกับWorkspace |
| 6 | Aแก้metadataตามphaseที่ยังอนุญาต | บันทึกข้อมูลจริง; กดยกเลิกฟอร์มแล้วข้อมูลไม่เปลี่ยน; ไม่มีProject delete |
| 7 | Aส่งคำเชิญ แล้วทดลองยกเลิก/อาจารย์ปฏิเสธก่อน | มีประวัติและสถานะถูกต้อง การตอบรับทำเป็นขั้นสุดท้ายของชุดคำเชิญ |
| 8 | advisorตอบรับคำเชิญใหม่ | ทีมเปลี่ยนอาจารย์ไม่ได้; advisorเห็นProjectในรายการที่ปรึกษา |
| 9 | Aโอนหัวหน้าให้B | Aเป็นmember/Bเป็นleaderหลังตรวจใหม่ สิทธิ์ย้ายตามจริง |
| 10 | Aออกเอง หรือBถอดAตามกรณีที่เลือก | AยังLoginได้แต่เสียสิทธิ์ทีม/Projectเดิม ไม่ลบProject |
| 11 | CเปิดWorkspace/Project | ไม่เห็นทีม/ProjectของA/Bจากการเป็นstudentอย่างเดียว |
| 12 | Logout/โหลดหน้า protectedใหม่ | กลับหน้าLogin และจบรอบด้วย Ctrl+C/ตรวจROLLBACKตามคู่มือUAT |

เลือก **ออกเอง** และ **ถอดสมาชิก** คนละรอบทดลองถ้าต้องการเห็นทั้งสองแบบ ไม่คาดหวังถอดสมาชิกที่ออกไปแล้ว หากมีTaskin_progressเงื่อนไขC-02อาจปฏิเสธตามกฎ ต้องบันทึกผลแทนการเปลี่ยนstatusอัตโนมัติ

## ช่วง B — สาธิตเมื่อข้อมูลก่อนหน้าและสิทธิ์พร้อมแล้ว

| ส่วน | Preconditions | วิธีสาธิต |
|---|---|---|
| Coordinator/กรรมการ | มีapproved Submissionและบัญชีadvisorที่พร้อมแต่งตั้ง กรรมการอย่างน้อย3คนก่อนVoteแรก | เพิ่ม/เปลี่ยน/ถอดก่อนVoteแรก แล้วลงVoteและแสดงว่ารายชื่อถูกล็อก |
| Topic votes | รอบล่าสุดผ่านอาจารย์/assignmentครบ ยังไม่ลงVote | ให้กรรมการทีละคนลงมติ แสดงprivacyก่อนครบ/ผลรวมหลังครบตามบทบาท |
| Evaluation | หัวข้อล่าสุดผ่านกรรมการ และมีcompleted Milestone≥1พร้อมassignmentที่ยังไม่ประเมิน | ให้คะแนน0และ100ตามข้อมูลทดสอบที่เตรียมไว้ ยืนยันimmutable/partialprivacy/รวม-เฉลี่ยหลังครบ |
| Error recovery | มีแผนยกเลิกnetworkอย่างควบคุมและสามารถคืนการเชื่อมต่อ | ดูผลจริงก่อนส่งซ้ำ ไม่อ้างว่าเกิดraceจากการคลิกซ้ำอย่างเดียว |

เส้นทาง Submission/Milestoneของเพื่อนยังไม่รวมในbranchนี้ จึงไม่ประกาศว่าสร้างpreconditionsช่วงBได้ครบด้วยUIจากช่วงA หากยังไม่พร้อม ให้บอกว่า **Not Ready** และอ้างผลอัตโนมัติที่มีอยู่ แยกจากการกดสาธิตจริง
