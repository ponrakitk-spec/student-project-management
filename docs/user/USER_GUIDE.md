# คู่มือผู้ใช้ — Student Project Management System

**ล่าสุด 2026-11-16:** มี Submission, Milestone และ Task/ผู้รับผิดชอบสำหรับทีมแล้ว ดู [รายงาน Task](../progress/TASK_IMPLEMENTATION_REPORT.md) และขั้นตอนด้านล่าง ทดลองเขียนผ่านโหมด 8001/ROLLBACK ตามคู่มือตั้งค่าทุกครั้ง ข้อมูลรอบทดลองจะถูกยกเลิกเมื่อปิด Backend

## งานย่อย ผู้รับผิดชอบ และการเปิดให้กรรมการประเมิน

1. นักศึกษาเข้าหน้า **โครงงาน → แผนงานโครงงาน → งานย่อยและผู้รับผิดชอบ** หัวหน้าสร้างงานย่อยได้ กรอกชื่อ คำอธิบายและวันกำหนดส่งที่ไม่บังคับ หากระบุวันต้องไม่ก่อนวันนี้ตามเวลาไทยและไม่เกินวันแผนงาน
2. เปิดรายละเอียดงาน แล้วหัวหน้าเลือกผู้รับผิดชอบจากสมาชิกปัจจุบันของทีม เลือกตนเองได้ ก่อนเริ่มงานหรือทำให้เสร็จต้องมีผู้รับผิดชอบอย่างน้อยหนึ่งคน
3. สมาชิกปัจจุบันเปลี่ยนสถานะงานที่ยังไม่เสร็จได้ แม้ไม่ได้เป็นผู้รับผิดชอบเองตาม V1 เมื่อทุก Task ของ Milestone เสร็จ ระบบเปลี่ยน Milestone เป็นเสร็จแล้วให้อัตโนมัติ ไม่แก้สถานะ Milestone ตรง ๆ
4. กรรมการเข้าหน้าบัญชี → **งานกรรมการ → ประเมินโครงงาน** จะให้คะแนนได้เมื่อหัวข้อรอบล่าสุดผ่านมติกรรมการครบตามกฎ และมี Milestone ที่เสร็จแล้วอย่างน้อยหนึ่งรายการ การทำ Task เสร็จไม่ข้ามขั้นลงมติหัวข้อ
5. หัวหน้าจัดการชื่อ/รายละเอียด/ผู้รับผิดชอบและลบงานได้ตามกฎ งานที่เสร็จแล้วต้องเปิดกลับเป็นกำลังดำเนินการก่อนแก้หรือลบ เปิดกลับได้เฉพาะหัวหน้าและต้องมีผู้รับผิดชอบอยู่
6. ถอนผู้รับผิดชอบต้องยืนยัน ระบบเก็บประวัติจริง และจะปฏิเสธหากทำให้งานที่กำลังดำเนินการไร้ผู้รับผิดชอบ ลบ Task ที่อนุญาตแล้วจะลบรายการผู้รับผิดชอบและประวัติของ Task นั้นตามกฎ
7. หลังคะแนนประเมินแรก การแก้งาน/แผนงาน/ผู้รับผิดชอบตามปกติถูกล็อก หากผลตอบกลับหายให้โหลดข้อมูลงานใหม่ก่อนทำซ้ำ

## ส่งโครงงานและให้อาจารย์ตรวจ

1. นักศึกษาเข้าหน้า **โครงงาน → ส่งโครงงานและประวัติ** ต้องมีทีม/Project และอาจารย์ตอบรับก่อน หัวหน้าทีมเลือก PDF หรือ PPTX หนึ่งไฟล์ ขนาด 1–4,000,000 ไบต์ แล้วกดส่ง สมาชิกอ่านประวัติและดาวน์โหลดได้
2. ระบบเก็บชื่อ/คำอธิบายโครงงาน ณ เวลาส่ง แสดงสถานะรออาจารย์ตรวจ ระหว่างรอตรวจจะส่งซ้ำไม่ได้ ประวัติแต่ละรอบและไฟล์เดิมยังอยู่หลัง refresh
3. อาจารย์เข้าหน้าบัญชี → **ตรวจโครงงานที่ปรึกษา** เลือกรอบที่ยังรอตรวจ ดาวน์โหลดไฟล์ แล้วเลือกอนุมัติหรือขอแก้ไข หากขอแก้ไขต้องมีคำแนะนำ กดบันทึกและยืนยันอีกครั้ง ผลตรวจบันทึกได้ครั้งเดียว
4. หากอาจารย์ขอแก้ไข หัวหน้าส่งไฟล์รอบใหม่ได้ ถ้าอาจารย์อนุมัติแล้วต้องรอขั้นตอนกรรมการตามกฎเดิม ผลอาจารย์อนุมัติยังไม่ใช่ผลหัวข้อสุดท้ายของกรรมการ
5. หากผลตอบกลับหายหรือเกิด error ให้กดตรวจประวัติก่อนทำใหม่ ห้ามกดส่งซ้ำเพื่อเดาว่าครั้งก่อนสำเร็จหรือไม่ ดาวน์โหลดต้องผ่านระบบและมีสิทธิ์ทุกครั้ง

## แผนงาน (Milestone) ของทีม

1. เข้าหน้า **โครงงาน → แผนงานโครงงาน** สมาชิกอ่านรายการได้ หัวหน้าทีมสร้าง/แก้ไข/ลบตามกฎ สร้างได้แม้ยังไม่ได้เชิญอาจารย์ ไม่ต้องรอผลหัวข้อเพื่อเริ่มวางแผน
2. กรอกชื่อ คำอธิบายที่ไม่บังคับ และวันกำหนดส่ง วันที่สร้างหรือเปลี่ยนวันกำหนดส่งต้องไม่ก่อนวันปัจจุบันตามเวลาไทยของระบบ ชื่อซ้ำใน Project เดียวกันไม่ได้
3. สถานะมาจากงานย่อย เปิดลิงก์ **งานย่อยและผู้รับผิดชอบ →** เพื่อจัดการ Task เมื่อทุก Task เสร็จ Milestone จะเสร็จตาม DB ไม่มีกล่องเลือกสถานะ Milestone โดยตรง
4. ลบต้องกดยืนยันและทำได้เฉพาะรายการที่ไม่มี Task การย่อวัน Milestone ต้องไม่ทิ้ง Task ที่กำหนดส่งช้ากว่าวันใหม่ (D-01) ระบบไม่เลื่อน Task ให้อัตโนมัติ
5. หลังมีคะแนน Evaluation แรก แผนงานจะอ่านได้อย่างเดียว และหากผลการเขียนไม่ชัดเจนให้โหลดรายการก่อนทำใหม่

## 1. ก่อนเริ่มใช้งาน

ทีมตั้งค่า Windows/PostgreSQLแยกเครื่องตาม [LOCAL_SETUP](../team/LOCAL_SETUP.md) และ [DATABASE_SETUP](../team/DATABASE_SETUP.md) ไว้ก่อน Git cloneได้โค้ดแต่ไม่ได้ฐานข้อมูล/บัญชี/manifestในเครื่องเจ้าของไปด้วย

การลองสมัคร/สร้างทีม/แก้ข้อมูลรอบนี้ให้เปิด API **8001แบบ ROLLBACK** ตามคู่มือ UAT หน้าเว็บใช้ `http://localhost:3000` และต้องชี้ APIไป8001 โหมดปกติ8000บันทึกข้อมูลเมื่อคำขอสำเร็จ จึงไม่ใช้ทดลองเขียนภายใต้ข้อจำกัดปัจจุบัน

บัญชีนักศึกษาสมัครผ่านหน้าเว็บได้ ส่วน advisor/coordinatorใช้บัญชีที่ผู้ดูแลเตรียมไว้ตาม [คู่มือ Advisor](../database/ADVISOR_ACCOUNT_PROVISIONING.md)/[Coordinator](../database/COORDINATOR_ACCOUNT_PROVISIONING.md) หากยังไม่มี ให้บันทึกว่ากรณีทดสอบขาดบัญชี ไม่เลือกroleจากหน้าสมัครหรือสร้างข้อมูลถาวรเพิ่มเอง

รหัสที่กรอกหน้า Loginคือรหัสบัญชีในแอป ไม่ใช่รหัส PostgreSQL `project_app` หรือ `AUTH_DB_PASSWORD` ไม่ใส่รหัสผ่าน/token/cookie/เนื้อหา `.env` ลงรายงานหรือ Git

## 2. สมัครสมาชิกและ Login

1. เปิด `/register` กรอกชื่อ อีเมล และรหัสผ่าน สมัครได้เฉพาะ student
2. อีเมลใช้รูปแบบทั่วไป เช่น `student01@example.test` ไม่ต้องมีกล่องอีเมลจริง ไม่จำกัด Gmail และไม่ส่งอีเมลยืนยัน
3. รหัสผ่านอย่างน้อย8ตัว มีตัวพิมพ์ใหญ่ A–Zและตัวเลข0–9อย่างละ1 ตั้งเองและจำไว้ ไม่กรอกpasswordในเอกสารนี้
4. กด **สร้างบัญชี** เมื่อสำเร็จจะไป `/login` แล้วกรอกอีเมล/รหัสผ่านเพื่อเข้าสู่ระบบเอง
5. Loginสำเร็จกลับหน้าบัญชี `/` แสดงชื่อ/อีเมล/บทบาท Sessionมีอายุ8ชั่วโมง ออกจากระบบได้ด้วยปุ่ม **ออกจากระบบ**

อีเมลซ้ำ/รูปแบบผิด/รหัสผ่านไม่ตรงจะมีข้อความแจ้ง ให้แก้ข้อมูลตามข้อความ ไม่สร้างบัญชีใหม่ซ้ำเมื่อยังยืนยันผลคำขอเดิมไม่ได้ อ้าง [Auth Contract](../api/AUTH_CONTRACT.md)

## 3. พื้นที่ทำงานและทางเข้าตามบทบาท

กด **พื้นที่ทำงาน →** จากหน้าบัญชี หรือเข้า `/workspace` โดยตรง ระบบตรวจ Loginก่อนอ่านข้อมูล มี loading/error/retryแยกจากสถานะไม่มีข้อมูล เมื่อกลับมาที่หน้า ระบบตรวจ sessionใหม่

| บทบาท | สิ่งที่หน้า Workspace แสดง |
|---|---|
| student | ชื่อทีม/หัวหน้าหรือสมาชิก และ Projectของทีม ถ้าไม่มีทีมแนะนำให้เริ่มทีมก่อน |
| advisor | ทางเข้าคำเชิญของฉัน, โครงงานที่ปรึกษา, งานกรรมการ |
| coordinator | ทางเข้าจัดการกรรมการโครงงาน |

Workspaceยังไม่มี Dashboard metrics/เปอร์เซ็นต์/กราฟ/Timeline/Contribution/Notification ตาม [Contract](../api/WORKSPACE_OVERVIEW_CONTRACT.md) อาจารย์ไม่ได้เป็นกรรมการทุก Projectเพียงเพราะเห็นเมนูงานกรรมการ Backendกรองงานที่ได้รับแต่งตั้งอีกครั้ง

## 4. นักศึกษา: ทีมและสมาชิก

### สร้างและแก้ทีม

1. เข้า `/teams` เมื่อยังไม่มีทีม กรอกชื่อ/คำอธิบายแล้วสร้างทีม ผู้สร้างเป็นหัวหน้าคนแรกใน transactionเดียว
2. ชื่อห้ามว่างหลังtrimและไม่เกิน255ตัว คำอธิบายไม่บังคับ มีชื่อทีมแล้วกด refreshตรวจข้อมูลได้
3. หัวหน้ากด **แก้ไขทีม** เพื่อแก้ชื่อ/คำอธิบาย กด **บันทึกการแก้ไข** หรือ **ยกเลิก** การแก้ต้องผ่านphaseของ SQLเดิม

### เพิ่มสมาชิก

1. นักศึกษาที่จะเพิ่มต้องสมัครแล้วและยังไม่มีทีม
2. หัวหน้าเข้า `/teams` กรอกอีเมลบัญชีนั้นตรงตัวและเพิ่มเป็น memberทันที ไม่มีขั้นตอบรับคำเชิญสมาชิก
3. สมาชิกอ่านรายชื่อทีมตนได้ แต่เพิ่มสมาชิกแทนหัวหน้าไม่ได้ รายการนี้ไม่เปิดอีเมลหรือ user directoryทั้งหมด
4. เพิ่มไม่ได้ถ้าบัญชีไม่พร้อม/มีทีมแล้ว/phaseไม่อนุญาต ให้ตรวจข้อความ ไม่ใช้บัญชีอื่นหรือเจ้าของDBข้ามกฎ

### โอนหัวหน้า ออก และถอดสมาชิก

- หัวหน้าเลือกสมาชิกปัจจุบัน กด **ตรวจสอบการโอนหัวหน้า** อ่านชื่อเป้าหมาย แล้ว **ยืนยันโอนหัวหน้า** หัวหน้าเดิมเป็น memberและเสียสิทธิ์หัวหน้า คนใหม่ได้รับสิทธิ์หลังโหลดข้อมูลใหม่
- memberกด **ออกจากทีม** และยืนยันได้ หัวหน้าต้องโอนก่อนออก
- หัวหน้าถอดได้เฉพาะ memberในทีมตน ต้องยืนยันก่อนดำเนินการ
- ถ้าการออก/ถอดจะทำให้ Task in_progressไม่มีผู้รับผิดชอบ ให้ระบบปฏิเสธทั้งคำขอ ไม่ถอนบางส่วนหรือย้ายงานให้อัตโนมัติ
- หลังออก/ถูกถอด บัญชีและLoginยังอยู่ แต่สิทธิ์ทีม/Projectเดิมสิ้นสุด ไม่ลบ Team/Projectเพื่อออกจากทีม

## 5. นักศึกษา: Project

ต้องมีทีมก่อนและหัวหน้าปัจจุบันเป็นผู้สร้าง หนึ่งทีมมีหนึ่ง Project สมาชิกอ่านได้จาก `/projects` หรือ Workspace

1. หัวหน้าเปิดหน้า Project กรอกชื่อ/คำอธิบายแล้วสร้าง สมาชิกที่ยังไม่มี Projectจะเห็นข้อความรอหัวหน้า
2. หลังสร้าง กด refreshแล้วข้อมูลยังอยู่ในรอบทดลองนั้น หัวหน้าแก้ชื่อ/คำอธิบายผ่านฟอร์มเดิมเมื่อphaseอนุญาต
3. เมื่อ SQLล็อกphaseแล้ว ระบบต้องปฏิเสธการแก้ ไม่เปลี่ยน snapshot/ประวัติรอบส่งย้อนหลัง
4. **V1ห้ามลบ Projectตาม R-01** จึงไม่มีปุ่มลบ ไม่ลบข้อมูลในDBเพื่อเริ่มdemoใหม่ ให้จบรอบ ROLLBACKแล้วเริ่มรอบทดลองใหม่ตามคู่มือแทน

อ้าง [Create Project](../api/PROJECT_CREATE_CONTRACT.md)/[Update Project](../api/PROJECT_UPDATE_CONTRACT.md)

## 6. ส่งและตอบคำเชิญอาจารย์

หัวหน้าไปหน้า Projectแล้วเปิด `/projects/advisor-invitations` เลือกชื่ออาจารย์ที่ผู้ดูแลเตรียมไว้แล้วกด **ส่งคำเชิญ** สมาชิกทั่วไปอ่านประวัติได้

| สถานะ | การใช้งาน |
|---|---|
| pending | หัวหน้ายกเลิกได้ อาจารย์ที่ได้รับคำเชิญตอบรับหรือปฏิเสธได้ |
| cancelled / rejected | เก็บประวัติเดิม รอบใหม่ทำตามตัวเลือกที่ระบบอนุญาต |
| accepted | อาจารย์เป็นที่ปรึกษา เปลี่ยนอาจารย์/ยกเลิกคำเชิญที่จบแล้วไม่ได้ |

อาจารย์ Loginแล้วเลือก **คำเชิญของฉัน** ไป `/advisor/invitations` อ่านบริบทแล้วกด **ตอบรับ** หรือ **ปฏิเสธ** ถ้าจะลองหลายผล ให้ลองยกเลิก/ปฏิเสธก่อนตอบรับ ไม่แก้ statusในDBเพื่อย้อนการตอบรับ

accepted Advisorเปิด **โครงงานที่ปรึกษา** ที่ `/advisor/projects` ได้ อ้าง [Invitations Contract](../api/ADVISOR_INVITATIONS_CONTRACT.md)

## 7. Coordinator: แต่งตั้งกรรมการ

หน้า `/coordinator/projects` แสดง Projectเมื่อมีหัวข้อที่อาจารย์อนุมัติแล้ว หากรายการว่าง ยังสรุปว่าเป็นbugไม่ได้ ต้องตรวจ preconditionก่อน ปัจจุบันเส้นทางส่งหัวข้อ/ตรวจหัวข้อของเพื่อนยังไม่ได้รวมใน branchนี้ จึงสร้างphaseดังกล่าวครบผ่านUIปัจจุบันไม่ได้

เมื่อมี Projectที่ตรงเงื่อนไขและเตรียมข้อมูลสำหรับUATไว้โดยได้รับอนุมัติแล้ว:

1. เข้า **จัดการกรรมการ** ของ Project เลือก advisorจากรายชื่อแล้วเพิ่มกรรมการ
2. กรรมการห้ามซ้ำและห้ามเป็น accepted AdvisorของProjectนั้น ต้องมีอย่างน้อย3คนก่อน Voteแรก ไม่ได้บังคับว่ามีได้สูงสุด3คน
3. เปลี่ยน/ถอดกรรมการได้ก่อน Voteแรก ใช้หน้าต่างยืนยันตามUI
4. หลัง Voteแรก รายชื่อถูกล็อกถาวร ไม่ปลดล็อกเองเมื่อมีรอบส่งใหม่

อ้าง [Committee Contract](../api/COMMITTEE_ASSIGNMENTS_CONTRACT.md) ไม่แก้ fixtureถาวร10+29+42แถวหรือสร้างLoginให้ usersของfixtureเพื่อสาธิตเอง

## 8. กรรมการ: ลงมติหัวข้อ

Loginด้วยบัญชี advisorที่ได้รับแต่งตั้ง เข้า **งานกรรมการ** → Project → หน้าลงมติ `/committee/projects/{id}/topic-votes`

อ่าน snapshotรอบล่าสุด เลือก **ผ่าน** หรือ **ขอแก้ไข** หากขอแก้ไขต้องมีความคิดเห็น ตรวจและยืนยันก่อนบันทึก ลงได้ครั้งเดียวต่อassignment/รอบส่ง แก้หรือลบย้อนหลังไม่ได้ หากมีรอบใหม่เข้ามาระหว่างอ่านให้โหลดข้อมูลใหม่ ไม่ส่ง Voteเดิมไปยังรอบใหม่อัตโนมัติ

| ผู้ดู | สิทธิ์ Vote |
|---|---|
| กรรมการ | เห็นVoteของตนและผลรวมเมื่อครบ ไม่เห็นVote/commentของกรรมการคนอื่น |
| สมาชิกทีม/accepted Advisor | เห็นรายชื่อกรรมการ; หลังครบเห็นdecision/commentsที่ไม่เชื่อมผู้เขียน ไม่เห็นVoteรายคน |
| Coordinator | เห็นVoteรายบุคคลเฉพาะ Project/รอบที่ตนมีสิทธิ์ |

ผลผ่านเมื่อมีมากกว่าครึ่งของกรรมการทั้งหมดให้ผ่าน เสมอไม่ผ่าน ไม่คิดจากเฉพาะคนที่ลงแล้ว อ้าง [Topic votes Contract](../api/TOPIC_VOTES_CONTRACT.md)

## 9. กรรมการ: Evaluation และอ่านผล

เข้า `/committee/projects/{id}/evaluations` ผ่านลิงก์ **ประเมินโครงงาน** ฟอร์มเปิดเมื่อหัวข้อล่าสุดผ่านกรรมการและมี derived completed Milestoneอย่างน้อย1รายการ ไม่บังคับให้ทุก Milestoneเสร็จ และไม่ตั้ง statusตรงเพื่อทำให้ปุ่มเปิด

กรอกจำนวนเต็ม0–100และความคิดเห็น ตรวจหน้าต่างยืนยัน แล้ว **ยืนยันบันทึกการประเมิน** บันทึกได้ครั้งเดียวต่อassignment/Projectไม่แยกรอบ คะแนน0เป็นคะแนนจริง ไม่ใช่สถานะยังไม่ประเมิน คะแนนแรกล็อก Milestone/Task/AssigneeตามV1 โดยข้อยกเว้นสมาชิกออกทีมยังอยู่ภายใต้ C-02

| ผู้ดู | ก่อนครบ | เมื่อครบ |
|---|---|---|
| กรรมการ | เห็นของตน | ของตน+รวม/เฉลี่ย ไม่เห็นรายคนอื่น |
| ทีม / accepted Advisor | ยังไม่เห็นผลคะแนนรวม | รวม/เฉลี่ยเท่านั้น |
| Coordinator | ยังไม่เห็นคะแนน/commentผู้อื่น | รวม/เฉลี่ยและคะแนน/commentรายบุคคล |

ทีมอ่านที่ `/projects/evaluations`, Advisor/Coordinatorเข้าจาก Projectที่มีสิทธิ์ เฉลี่ยปัดเป็นจำนวนเต็มจากSQL อ้าง [Evaluation Contract](../api/EVALUATIONS_CONTRACT.md)

## 10. เมื่อพบข้อผิดพลาด

- **ยังโหลดไม่ได้/เครือข่ายขาด:** ใช้ลองอีกครั้ง/ตรวจข้อมูลใหม่ ไม่ตีความว่าไม่มีทีม/Project
- **ยังยืนยันผลการบันทึกไม่ได้:** อ่านข้อมูล/ประวัติล่าสุดก่อนส่งซ้ำ ระบบไม่ auto retryคำขอเขียน หากคะแนนหรือVoteบันทึกแล้วจะเห็นของตนหลังโหลดใหม่
- **Sessionหมดอายุ:** กลับLogin ไม่ใส่passwordหรือCSRFtokenในURL/รายงาน
- **สิทธิ์ไม่พอ/ไม่พบProject:** ตรวจบัญชี บทบาท สมาชิกภาพ และassignmentปัจจุบัน ไม่เปลี่ยนURL/IDsหรือใช้ownerข้ามสิทธิ์
- **Task/Projectถูกล็อกตามphase:** บันทึกผลที่ระบบปฏิเสธตามกฎ ไม่แก้ Schema/DBflagsเพื่อให้ทำรายการผ่าน

ใช้ [แบบบันทึก UAT](../uat/MANUAL_UAT.md) ใส่ขั้นตอน/ผลคาดหวัง/ผลจริง/ข้อความที่ไม่มีsecrets การทดลองด้วย UIไม่ใช้แทนหลักฐานDBconcurrencyหรือการทดสอบระบบครบทุกRequirement
