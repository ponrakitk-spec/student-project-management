## จุดติดก่อนรันหรือรวมงาน

### B01 — Test fixture ยังมีทางหลุดจาก outer ROLLBACK (ต้องแก้ก่อนรัน DB tests)

- ใน `backend/tests/test_submission_api.py:44` เรียก `TeamAPIIntegrationTests.setUp` แล้ว override เฉพาะ `get_submission_uow`
- Base setup มี `get_auth_uow` และ `get_team_uow` แต่ไม่มี `get_project_uow`/`get_invitation_uow`
- `project_with_advisor` เรียกสร้าง Project และส่ง/ตอบรับ Invitation ผ่าน HTTP จึงอาจใช้ production UOW ที่เปิด connection ใหม่และ COMMIT เอง หรือมองไม่เห็น Team fixture ที่ยังไม่ COMMIT ไม่ใช่ outer rollback เดียวกัน
- แนวทางให้เพื่อนแก้/รับช่วงเมื่ออนุมัติ: override Project และ Invitation UOW ด้วย connection fixture เดียวกัน ตรวจ test DB/effective role ก่อนชุด และ snapshot หลัง rollback; ไม่ใช้ COMMIT fixture แก้ปัญหาการมองเห็น
- หลาย assertions ในชุดใหม่ใช้จำนวน submission เท่ากับ 0 แทน baseline+delta ต้องทบทวนเพื่อรักษาข้อมูลเดิมในเครื่องผู้พัฒนา
- รอบนี้ไม่รัน suite นี้ จึงไม่มี SQLSTATE หรือผล failure จาก PostgreSQL ให้รายงาน ไม่เดาสาเหตุ setup failure ที่เอกสารเพื่อนเคยกล่าวไว้

### B02 — Connection policy ขัดกับขอบเขตที่เจ้าของยืนยัน

- `backend/auth_store.py` เพื่อนเพิ่ม `AUTH_DATABASE_URL`, `AUTH_DB_NAME`, `AUTH_DB_USER`, auth schema และ owner role ที่เปลี่ยนได้ และมี Supabase SQL/docs ใหม่
- Default ยังเป็น `student_project_management_v1_test`/`project_app`; การทดลองด้วย config จำลองและ mocked connect ยืนยันว่าตั้ง DB/user อื่นแล้วถูกใช้เป็นเป้าหมายได้จริง ไม่ได้เชื่อม DB ใดในการทดลอง
- จึงไม่เอา config/connection ของเพื่อนมารวมโดยอัตโนมัติ ต้องคงนโยบายใช้ test DB/project_app เดิมจนเจ้าของอนุมัติขอบเขตอื่น ไม่รัน Supabase bootstrap หรือ role scripts
- เจ้าของยืนยันเพิ่มว่า Supabase เตรียมไว้สำหรับอนาคต; ยังไม่ใช่การอนุมัติให้เปลี่ยน runtime ปัจจุบันหรือใช้ DB อื่น งานตอนนี้คง PostgreSQL/test DB แยกเครื่องตามเดิม

### B03 — shared tests/เวลารอ/ความครบของ snapshot

- เพื่อนเพิ่ม routes ใน `backend/main.py` แต่ `backend/tests/test_auth_security.py` ยังเหมือนฐานเดิมและ assert OpenAPI paths แบบ exact set ที่ยังไม่มี Submission จึงคาดว่าจะ fail เมื่อ import dependencies ครบ (ข้อสรุปจาก source ไม่ใช่ผลรัน suite เพื่อน)
- `submission_transaction_on` ใช้ connection opener ร่วม แต่ไม่ได้ SET LOCAL timeout เอง ขณะที่ opener รุ่นเพื่อนย้าย timeout ไปเฉพาะ Auth transaction ต้องทบทวนให้ Submission/Team/Project/Invitation ยังมี timeout ตามเดิมก่อนรวม connection change
- remote เพื่อนมี tracked `__pycache__/*.pyc` 17 ไฟล์ ไม่รับ generated artifacts เหล่านี้เข้าชุดรวม
- Tip เพื่อนไม่มีไฟล์ฐานเจ้าของ 52 ไฟล์ รวม Frontend Auth/Team/Project/Invitations, tests, env examples, ignore/attributes และ docs/team/backlog; ไม่ copy ทับหรือ checkout branch เพื่อนมาเป็นฐานต่อทั้งหมด
- Ancestor เป็น main รุ่นแรก: การขาดไฟล์ใน tip ไม่ได้พิสูจน์ว่า merge จะลบไฟล์ของเรา ต้อง review merge diff/conflicts ของจริงต่างหาก

## แผนเชื่อมต่อแบบรักษางานทั้งสองฝ่าย

1. Pin snapshot เพื่อนและให้เจ้าของยืนยันขอบเขตผู้รับผิดชอบ/Submission Contract ก่อนแก้หรือรับช่วง runtime
2. ให้เพื่อนแก้ B01 ใน branch ของตน หรืออนุมัติให้รับช่วงเฉพาะรายการนั้น ตรวจและทดสอบโดยไม่เปลี่ยน Schema/RBAC
3. จากฐานเจ้าของที่มีระบบเดิมครบ พิจารณารับ source Submission3ไฟล์ + tests3ไฟล์ + Contract เมื่อยืนยันแล้ว แยก connection/Supabase ออกให้รอข้อสรุป ไม่ cherry-pick upload commit ทั้งก้อน
4. ผสานเฉพาะ Submission router/error/no-store/body-limit/CORS order ใน main และ UOW override ใน Browser harness พร้อมอัปเดต OpenAPI expectations เมื่อ scope ได้รับอนุมัติ ไม่เขียนทับไฟล์ shared ทั้งไฟล์
5. ทบทวนและติดตั้ง dependencies ใน venv เมื่อรับขอบเขตแล้ว; รุ่นที่เพื่อน pin คือ python-multipart0.0.33/pypdf7.0.0/python-pptx1.0.2 ข้อมูลนี้มาจาก source ไม่ใช่คำรับรองความเข้ากันได้/ความปลอดภัยหรือการเลือกเวอร์ชันใหม่
6. ทดสอบ offline ก่อน แล้ว direct project_app + HTTP integration บน test DB เท่านั้น ทุก fixture ใช้ outer transaction/ROLLBACK และตรวจคืน metadata/ACL/rows; ห้ามใช้ owner ข้ามสิทธิ์ของ positive business request
7. หลัง Backend ผ่าน จึงเชื่อม Frontend Submission หากเพื่อนยังไม่ได้ทำและอนุมัติรับช่วงแล้ว เพิ่ม UOW override ก่อน Browser POST และรักษา Auth/Team/Project/Invitations เดิม

รอบตรวจ branch ก่อนอนุมัติ feature ทำเฉพาะการตรวจและบันทึก ไม่มี DB connection ต่อมาผู้ใช้อนุมัติ Project update แล้วจึงทดสอบ test DB ตาม [รายงานรอบพัฒนา](../progress/PROJECT_UPDATE_IMPLEMENTATION_REPORT.md) ไม่มีไฟล์ runtime ของเพื่อนถูกเปลี่ยน ไม่มีการส่งข้อความหาเพื่อน/Commit/Push/merge
